## Part A – Backend (API Server) Hardening & Improvements

### 1. Security Middleware (Add to `api-server/src/app.ts`)
- **Rate Limiting:** Install `express-rate-limit`. Apply different limits per route group:
  - `/api/auth/*` – 5 requests per minute per IP
  - `/api/bookings/*` – 20 requests per minute per IP
  - `/api/*` – 100 requests per minute per IP
- **Helmet.js:** Add `app.use(helmet())` to set security headers.
- **CORS:** Restrict origins to your Replit frontend URLs only (e.g., `https://quick-book-clone--surya25sp.replit.app`). Do not use `*`.
- **Ownership Middleware:** Create middleware that verifies the authenticated user’s ID matches the resource owner (e.g., when accessing a booking). Apply to all `GET /api/bookings/:id` and `PATCH /api/bookings/:id/cancel` routes.

### 2. Input Validation & Sanitisation
- Every endpoint already uses Zod (keep this). Add `.refine()` or `.superRefine()` to prevent past dates for bookings and nonsensical values.
- Sanitise string inputs with `.trim()` and `.max()` limits.

### 3. Slot Availability Accuracy (Critical)
- In `GET /api/businesses/:id/slots`, replace the current random‑ish `spotsLeft` generator with a **real booking count** query.
- Count existing confirmed bookings for that business, service, date, and time slot from the `bookings` table. Subtract from the service’s `capacity` (or a default of 1 per time slot if no capacity field). Return the actual `spotsLeft`.

### 4. Audit Logging
- Ensure all admin actions (like manual cancellation by provider, super‑admin disputes) are already logged. For customer actions, log booking creation and cancellation in a simpler `audit_logs` table (if needed later).

### 5. Environment Variables
- Move all secrets (JWT secret, database URL) to `.env`. Validate they exist on startup.
